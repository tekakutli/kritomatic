kritomatic-xremap
=================

A keymap config generator and xremap launcher for the kritomatic script
collection. Bind keys — on your physical keyboard, or on any virtual
device emitted by kanata, keyd, interception-tools, kmonad, etc. — to
capabilities: named commands the project ships.


The two-file model
------------------

Everything you configure lives in one of two files:

    capabilities.yaml                (shipped by the project)
        The menu of what can be invoked. Maintainer-owned.
        Users do not edit this file. Each entry names a capability
        and the command template that runs it.

    ~/.config/kritomatic/bindings.yaml (owned by you)
        Which key on which device runs which capability.
        Seeded once from bindings.example.yaml; thereafter it is yours.
        Nothing in the project overwrites it on upgrade.

There is no shared editing surface. Adding a new capability means the
maintainer adds one entry to capabilities.yaml; users get it for free
without editing anything. Changing your keyboard means you edit one
list in your bindings.yaml; the project never sees the change.


Files
-----

    kritomatic-xremap.py        The render / validate / run launcher.
    capabilities.yaml           Shipped menu of capabilities.
    bindings.example.yaml       Template for a new user.
    scripts/                    The scripts that capabilities invoke.
    xremap-kritomatic.service   systemd unit that runs the launcher.
    xremap-kritomatic.path      Watches bindings.yaml for changes.
    setup_links.py              First-run installer; safe to re-run.

See INSTALL.md for step-by-step setup.


Commands
--------

    kritomatic-xremap.py init
        Seed ~/.config/kritomatic/bindings.yaml from
        bindings.example.yaml. Refuses to overwrite without --force.

    kritomatic-xremap.py render
        Print the exact xremap config that `run` will execute.

    kritomatic-xremap.py render --out FILE
        Same, but write to a file.

    kritomatic-xremap.py validate
        Structural check: every capability exists, every referenced
        script file is on disk, no block filters on a device that
        devices.listen doesn't cover.

    kritomatic-xremap.py validate --router
        Also check that every file referenced by scripts/router.py's
        TOOLS dict exists.

    kritomatic-xremap.py run
        Render and launch xremap. This is what systemd invokes.


Debugging a binding that doesn't fire
-------------------------------------

1.  ./kritomatic-xremap.py validate
    Names anything structurally wrong: unknown capability, device
    not in devices.listen, script file missing.

2.  ./kritomatic-xremap.py render
    Shows the exact xremap config. Confirm the launch array and the
    device filter on the block.

3.  pgrep -af xremap
    Shows the running xremap and its --device list. If your device is
    not there, edit devices.listen in bindings.yaml.

4.  journalctl --user -u xremap-kritomatic -n 50
    Shows the launcher's stdout/stderr from the last start.
